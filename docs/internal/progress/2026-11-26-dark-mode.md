# Dark mode: `prefers-color-scheme` follows the desktop

## Problem

bare always answered `prefers-color-scheme: light`. The cascade (`@media`) and `matchMedia` read a fixed value. T3 Code and other
pages stayed light on a dark desktop.

## Change

- New `crates/os/src/scheme.rs`: `prefers_dark()`.
  - `BARE_COLOR_SCHEME=dark|light` wins.
  - On Linux it reads `gtk-application-prefer-dark-theme` from `$XDG_CONFIG_HOME/gtk-4.0/settings.ini`, then `gtk-3.0`.
  - Elsewhere the scheme is light.
- `crates/css/src/at_rules.rs`: one process flag (`AtomicBool`), `set_prefers_dark` and `color_scheme()`. `media_matches` reads it.
- `crates/bare/src/browser_platform.rs`: `media_environment()` reports `color_scheme()`.
- `crates/bare/src/main.rs`: `show_interactive` (window mode) sets the flag once at start. Drivers, `bare-mcp` and tests stay light.

## Gaps

- The XDG desktop portal (`org.freedesktop.appearance color-scheme`) is not read: it needs D-Bus.
- A change of the desktop scheme while bare runs is not seen. A `change` event on `matchMedia` does not fire.
- The scheme is the same for all pages of one process.

## Tests

- `crates/os/src/scheme_tests.rs`: the environment override and the GTK file parse.
- `crates/css/tests/prefers_dark_tests.rs`: `media_matches` before and after `set_prefers_dark(true)`. It is an integration test, so the
  global flag does not leak into other tests.

## Cost

No cost rows run. The change adds one relaxed atomic load per `prefers-color-scheme` feature in a query, and one small file read
at window start.

## test262

Not affected (no Vex change).

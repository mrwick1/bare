# `env()` in CSS values (OFS-52)

## Change

- A declaration with `env()` was dropped. So `padding-left: max(16px, env(safe-area-inset-left, 0px))` gave 0, and `CSS.supports` gave false.
- `var::substitute_env` replaces each `env()` with the value of the browser, or with its fallback. The safe-area insets, the max insets and the keyboard insets are `0px`: a window has no notch and no on-screen keyboard. Another name takes its fallback.
- `parse_declaration` replaces `env()` only after the value failed to parse (`with_env`, cold). A good declaration does not pay for it.
- `env()` works in a custom property and around `var()`: the `var()` path calls `parse_declaration` on the substituted text.
- `var::find_var` is now `find_fn`, with the function name as a parameter. It is `#[inline(always)]`, so `has_var` keeps a constant name.

## Tests

- New: `env_tests` (`bare-css`). Three of its four tests failed before the fix.
- `cargo test --locked -p bare-css`: pass.
- Release `bare-drive`, headless, a local page: `CSS.supports('padding-left', 'env(safe-area-inset-left, 0px)')` is true. The computed `padding-left` of `max(16px, env(...))` is `16px`. An unknown name takes its fallback, and `env()` in a custom property works. Before, every check failed.

## Not tested

- `env()` with no value and no fallback drops the declaration. Chrome makes it `unset`, and `CSS.supports` gives true for it.
- `titlebar-area-*` and `viewport-segment-*` take the fallback.
- `env()` in a media query or in `@supports` conditions other than a declaration.
- Windows: the change is platform-neutral Rust. Not run on Windows.

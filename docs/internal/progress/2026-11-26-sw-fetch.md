# Fetch interception by a service worker (design-service-workers.md, step 7)

## Change

- A `fetch()` of a controlled page goes to the active worker of its controller as a `fetch` event (`FetchEvent`). The page sends the
  request as data: URL, method, header lines, body bytes, mode, credentials, redirect (`sw_hub.rs` `FetchReq`, op 30).
- The worker side makes a new `Request` and fires `FetchEvent` with `clientId`. `respondWith(p)` waits for `p`, reads the body of
  the `Response` and sends status, status text, header lines, bytes and URL back (op 32). The page gets them through its inbox
  (`ToClient::Fetched`) and makes a new `Response`. A response with no URL takes the request URL (Fetch, "main fetch").
- No `respondWith` in the dispatch, an event that ends with no reply, a worker that stops, or a request that the worker cannot
  make: the page goes to the network with the same request (op 31, `browser_fetch::fetch_args`).
- A rejected promise or a value that is not a `Response`: the fetch rejects with `TypeError: Failed to fetch` (Chrome).
- `respondWith` throws `InvalidStateError` as Chrome does: a second call ("The event has already been responded to.") and a call
  after the dispatch ("The event handler is already finished.").
- After the script of a version runs, the host reads whether the worker global has a `fetch` listener (`Ver::has_fetch`). A worker
  with no listener gets no `fetch` event and does not start for a fetch.
- A `fetch()` inside the worker goes to the network (the worker is not a client).

## Cost when the page has no registration

`browser_fetch::fetch` reads one `Cell` (the client id of the page) and goes on as before. The interception path is `#[cold]`.

## Known deviations

- Only `fetch()` of a window is intercepted. Scripts, style sheets, images, `XMLHttpRequest`, the fetches of a dedicated worker
  and navigations (step 8) go to the network.
- `preloadResponse` is a promise of `undefined` (no navigation preload). `replacesClientId` and `resultingClientId` are empty.
- The body of a request and of a response crosses as one byte copy; no streams.
- An `AbortSignal` of the page does not reach the worker. It acts on the network fallback only.

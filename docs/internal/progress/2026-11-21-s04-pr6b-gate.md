# 2026-11-21: S0.4 PR 6b, the grep gate for the old engine in `crates/bare`

Branch `t3/s04-pr6b-gate`, on top of PR 6a (#841).

## What changed

- `crates/bare/src/old_engine_gate_tests.rs`: a test that scans `crates/bare/src` (not `*_tests.rs`) for two things: the path `bare_js::` (the old engine crate: `Interp`, `Value`, `ObjId`, `Heap`) and the field `Browser::it` (`.it` not followed by an identifier character or `(`; `x.it()` of the `Entry` trait is not the field).
- `crates/bare/old_engine_files.txt`: the files that may do so, with the tag of each (`engine`, `it`). It has 90 files today; 16 use the field `it`.
- The test fails when a file that is not on the list names the engine, when a file has a tag that its line does not give, and when a line names a file or a tag that is gone. The list can only get shorter. At the end of S0.4 only `src/browser_session.rs` stays.
- Negative check: one line `// bare_js::eval::Interp` in `src/agent.rs` fails the test with "src/agent.rs: names the old engine (engine) and is not on old_engine_files.txt". It passes again when the line is removed.

## What I did not do: move the `Browser::it` uses to the facade

The 72 uses are not engine calls that a facade method can hide. 52 are `self.it.host_scope(|it| ...)` with a closure that takes `&mut Interp` and calls a `Dom` method that takes `&mut Interp`; 21 are the module loader (`module_parse`, `module_link`, `persist_value`). A facade method for each would still name `Interp` in its signature. The uses go when `Dom<E: Engine>` makes those methods generic. So 6b adds the gate, and the move waits for 6c's design choice (see the PR text).

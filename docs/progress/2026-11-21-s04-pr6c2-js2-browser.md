# 2026-11-21: S0.4 PR 6c-2, the browser runs pages on js2 (`BARE_JS_EXEC=new`)

Branch `t3/generic-engine-js2-impl`, stacked on `t3/generic-engine-js2-browser` (PR 6c-1, #849). Owner decision 2026-11-21: design B. The old engine stays the default.
Previous entry: [PR 6c-1](2026-11-21-s04-pr6c1-generic-engine.md).

## What changed

- New `crates/bare/src/eng_new.rs`. It has the marker `New`, `impl Eng for New` and `impl Ops<New> for Realm` (js2). All 103 operations exist.
  An object, a string, a symbol and a key are a js2 `Value` in the newtype `NV`. js2 cells do not move, so a value is a stable id while its object lives.
  The operations use the handle API of `Engine` and the raw helpers below. Each handle stack of a call is cut back when the call ends.
- `SlotKey::DENSE`: `IdTab` (the table that is indexed by object slot) has a sparse map for a key that is a pointer. The old engine keeps the dense form,
  and the choice is a constant, so its code does not change.
- New `crates/bare/src/browser_any.rs`. `AnyBrowser` is `Old(Browser<Old>)` or `New(Browser<New>)`. `AnyFault` is the fault of either engine.
  `Session`, `Page`, `control`, `images` and the driver (`crates/drive`) hold `AnyBrowser` and call its methods.
  Each method forwards to the browser of the variant (two small macros, `fwd` and `fwd_try`). No type of an engine is in a result.
  The script calls of the driver (`eval`, `Check::Js`, `title`, the page text) use `script`, `script_text`, `script_true`, `promise_step` and `fault_text`.
  A value that waits across turns of the page loop is a `Persistent`.
- `Session::load::<E>` is the setup of a new document, made generic: it takes the browser of the engine that `SessionConfig::js2` selects.
  `SessionConfig::js2` is set from `BARE_JS_EXEC=new`. `exec_from` no longer fails: `new` gives the default old mode, and the session reads the flag.
- `Ops::h_str_units` returns a `Cow`. The old engine borrows, js2 makes the units (a rope has no flat slice).
- js2, in `crates/js2/src/api*.rs` only:
  - `api_raw.rs` (new): `raw_units`, `raw_intrinsic`, `raw_callable`, `raw_promise`, `raw_new_target`, `raw_host_key`, `raw_collect`. These read the realm with `&self` (or collect it between tasks).
  - `Realm::raw_persistent`, `Realm::raw_own` (an own property with its attributes).
  - `Engine::own_kind` (the host read an own property: the trait default was `Unsupported`).
  - `Engine::set_integrity` (`Object.freeze` and `seal`, `false` for a host-filled object).
  - `Engine::construct` of a class (it ran `Unsupported("construct of a class")`). It runs as a nested call, as `Reflect.construct` does, so no collection runs until the class returns.
  - Bug fix in `hs_walk` (`api_host.rs`): a plain function made no `prototype` when its chain had a host object. In a browser realm every `function C() {}` had `C.prototype === undefined`.
- The tests and the examples use the old engine through `Deref` of `AnyBrowser` to `Browser<Old>`. It panics on js2. The product code does not use it (the lib, `bare-drive` and `bare-mcp` compile without it).
- `crates/bare/examples/type_load.rs` runs on js2 (`BARE_JS_EXEC=new`). `LOGS=1` prints the console, the listener errors and the failed requests of the page. The old-engine statistics (steps, heap footprint) print only for the old engine.
- `old_engine_files.txt`: `page.rs` out, `browser_any.rs` and `eng_new.rs` in (40 to 41 entries). `bare_js::` in `crates/drive/src`: 8 lines down to 1.

### Approximations and stubs in `eng_new.rs` (no journey needs them yet)

- `h_symbol_description` (a `&self` read): `Unsupported`.
- `set_wall_clock` with a virtual clock: `Unsupported`. A session with `virtual_clock` on js2 is not tested.
- `Intrinsic::IteratorPrototype` for a `&self` read: the object prototype, until the first `Engine::intrinsic` ask.
- `is_constructor_value`: any callable (an arrow or a method counts).
- `inspect_o`: the plain text of the value (`display`), not the compact JSON of the old engine. `bare-drive eval` on an object gives `object` on js2.
- `collect` returns zero counts. `external_live` is 0 and `add_external` does nothing, so the collect trigger of the page uses only the growth of the node arena.
- `bytes_of` and `api_args_slice` give `None`: a call that reads its arguments copies them.
- `set_sources` does nothing.
- A class construct from the host holds the collector until the constructor returns.
- Seen in a probe, not investigated: `String(div.style)` is `[object Date]`, and `String(document.createElement('div'))` is `[object HTMLElement]`.
- js2 itself: `typeof (() => 1).prototype` is `object` (an arrow function makes a `prototype`).

## Cost rows

Tool: `tools/js/cost_matrix.sh`. BASE is the 6c-1 head ca937a5b, NEW is this branch. Instructions of user mode, minimum of 3 runs, machine archMachine under load. Rows: the 176 rows of the `bare` examples (the families that 6c-1 measured). The old engine runs them, so this PR must not change them.

**Result: the rule passes.** Default profile, 176 rows: mean +0.003% (glibc). One row is over under one allocator only, and its jemalloc run is +0.514%:

| Row                           | glibc base | glibc new | change | jemalloc change |
| ----------------------------- | ---------- | --------- | ------ | --------------- |
| session_load chain 1          | 5201008    | 5257767   | +1.09% | +0.51%          |

Second run of the `session_load` rows with `RUSTFLAGS="-C codegen-units=1"` on both trees (4 rows, jemalloc on every row): `chain 1` is +1.07% (glibc) and +0.47% (jemalloc).

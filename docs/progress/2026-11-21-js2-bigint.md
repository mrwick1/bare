# 2026-11-21: BigInt in js2

## Design

Use the reserved BigInt NaN-box tag for a pointer to an immutable word cell.
Reuse the leaf layout and allocator for RegExp words. Store the sign in the
header and place the little-endian 64-bit limbs after it. Zero has no limbs.
The collector can mark the cell without tracing or running a finalizer.

A tagged inline integer would avoid allocation for small results. It would
also require a payload check wherever the collector interprets pointer tags.
An external digit buffer would require a second allocation and a finalizer.
Start with one cell per value. Compare and hash the sign and limbs by value.

Reuse the old engine's sign-magnitude arithmetic and text conversion.
Operands borrow their limbs. Arithmetic uses scratch buffers for its result.
This keeps the existing division and Karatsuba multiplication algorithms and
adds no dependency. Keep number dispatch first and handle BigInt on the
slow path. The value and object headers keep their current sizes.

## Checks

Compare test262 on the same subset before and after the change. Measure the
five interpreter rows and startup on archMachine with three runs per
allocator. Run Miri on the cell and GC paths.

## Implementation

Load literals at a GC safepoint. Route arithmetic and conversions to the BigInt
code after the Number path. Compare BigInts exactly with numbers and integer
strings. Map and Set hash and compare their limbs. Install the BigInt
constructor and prototype on first use. Match the existing Number locale
fallback with exact decimal digits and en-US grouping.

Run JSON's toJSON method and replacer before checking for BigInt. Expose the
same limb count and type to the host that the old engine exposes.

## BigInt workloads

Measured on archMachine with glibc. Values are the minimum user-mode
instruction counts of three runs. The old engine uses the bytecode mode of
`bigint_load`. js2 runs the same scripts with `script_run`. Both runners check
the result. The counts include setup and each runner's result check.

| Workload | Old engine | js2 |
| --- | ---: | ---: |
| Small, 100,000 turns | 377,660,618 | 401,515,078 |
| Heap mix, 20,000 turns | 252,511,776 | 129,920,060 |

The old engine stores small integers inline. js2 allocates cells for these
integers. Hypothesis: this accounts for part of the cost of the small loop.

three `perf stat -e instructions:u` runs with each allocator. Startup runs

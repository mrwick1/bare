## 2026-11-21: S0.4 PR 5, owners, trace and prune of the browser tables on the interface

Status: built and tested. The cost rule passes (default build, or `codegen-units=1` for two rows). See "Cost" below. This PR has no auto-merge. The main session decides.

### What changed

Every table of the browser in `crates/bare` now has an owner key, a `trace` and a `prune` on `bare_js_api::Host`. No function of the browser calls `Host::roots(out: &mut Vec<Value>)` or `Host::prune(live: &dyn Fn)` of the old engine any more.

- New `Owner` kinds: `Port`, `Worker`, `Mql`, `Frame`, `TokIter`, `Resize`, `Mo`, `Io`, `Walk`, `Range`, `Sel`, `Attr`, `Web`, `Geom`, `Idle`. An object of these kinds gets its key at creation (`Dom::own_obj`, `State::add_target`).
- The global object is the owner `Owners::win`. Its `trace` visits the roots of the realm life (`Dom::trace_roots`, the old `roots` body). The 26 `*_roots` functions keep their names and take `&mut Roots` (`browser_sources.rs`), an adapter over `Tracer`.
- `Host::trace` has one arm for each new kind. `Host::prune` gets the keys of the dead owners and frees the entries of each dead object. The kinds with a list or a total (`Resize`, `Mo`, `Io`, `Walk`, `Range`, `Attr`, `Web`) are freed in one batch for each kind.
- An event target object (`Target::Obj`) is registered at creation. Its entry in `by_obj`, its listeners and its kind tables end with it. `Owners::objs` maps the object to its key.
- `Browser::collect` calls `reclaim_wanted` after the engine collection.
- The old `impl eval::Host for Dom` keeps three methods: `call` (returns `Unsupported`), `fill_indexed` and `named_write`.

### What remains for PR 6

- `fill_indexed` and `named_write` have no method on `bare_js_api::Host`. The old impl stays for them. PR 6 needs a trait change: either two new methods, or a different way for the engine to ask for the indexed and named writes of a host object. This blocks the removal of the old `impl`.
- `Dom` is not yet generic over `Engine`. The `Roots` adapter and `Tracer<Value>` still use the old engine `Value`.
- Install functions are not touched (PR 4).

### Behavior differences

- Before: one `prune(live)` ran in every collection and walked each table. Now `prune` runs only when an owner died, and frees only the dead entries.
- Before: the `Attr` objects and the other new kinds had no owner key. Their entries were found by a walk of the table in `prune(live)`. Now each follows its own key.
- `IdTab` and `IdMap` check the generation. A stale entry never reaches a new object. Pruning only frees memory and keeps the counts right.

### Cost

Machine archMachine, load from other agents. Instruction counts (`tools/js/cost_matrix.sh -g`, minimum of 3 runs of `perf stat -e instructions:u`), so the load does not change them.

First measure (base `origin/main` 2f12c3f6, 167 DOM rows): 4 rows over +0.5% under both allocators. `attr_load react 1` (+0.650%) and `react 10` (+0.714%) also failed at `codegen-units=1` (+0.622%, +0.669%). Cause (callgrind): about 230 instructions for each `Attr`, from one hash removal in `attr::forget`, one push into the engine owner list, and the `prune` loop.

Fix: `Tables::attrs` is now an `IdTab<ObjId, AttrObj>` (was `IdMap`). `attr::forget` removes a dead `Attr` with an index write and no hash. It frees the empty pages once for each batch. `IdTab` has a new `iter_mut` for `pins`. The push into the engine owner list stays (it is in the engine).

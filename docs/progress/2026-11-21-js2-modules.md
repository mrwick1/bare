# js2: ES modules and import() (2026-11-21)

Branch `t3/js2-es-module-support`, based on main 2f12c3f6. Design: `../design-js2-host-api.md` section 12.

## What changed

- js2 answers the nine module methods of `bare-js-api` (`module_parse`, `module_requests`, `module_set_requested`, `module_url`, `module_link`, `module_evaluate`, `take_dynamic_imports`, `finish_dynamic_import`, `reject_dynamic_import`, `fail_dynamic_import`). They were `Unsupported`.
- Static `import` and `export` (named, default, `* as`, re-exports, `export *`), live bindings, cycles with hoisted functions, the dead zone, `import.meta.url` and `import()` from classic scripts and modules.
- A module is one function with a `phase` parameter. A binding that is exported, and every import, is a property of an environment object. Reads use `GetCtxField`. No interpreter op is new.
- New files: `compile_module.rs`, `module.rs`, `api_module.rs`, `module_tests.rs`. The compiler change for classic code is one field (`LevelVar.env`) and one flag (`Res::Ctx.env`).
- Test runner: `crates/js-diff/examples/test262_modules.rs` runs `module` tests and `import()` tests on both engines. It is in its own PR (branch `t3/js2-test262-modules`) because this change is over 1,000 lines.

## test262

`language/module-code` and `language/expressions/dynamic-import`, 1,604 files, 466 skipped by the rules of `tools/fixtures/js/test262-js2-skip.txt` (without the `allow:` lines). 1,138 run. Runner: `test262_modules ENGINE ROOT SKIP LIST`.

|                     | old engine | js2 |
| ------------------- | ---------- | --- |
| pass                | 1,090      | 621 |
| fail                | 48         | 517 |
| module-code pass    | 549        | 285 |
| dynamic-import pass | 541        | 336 |

No test passes on js2 and fails on the old engine. 469 tests pass on the old engine and fail on js2. They fail for engine features that js2 does not build yet, not for module code:

- top-level await: 213 (`unsupported: top-level await`)
- async functions: 167, generators: 48, Function constructor: 32, `Reflect`: 28, `with`: 6, `Date`: 1 (the counts overlap).
- 6 tests use `Promise.all(...).then(([a, b]) => ...)`. A classic script with the same code fails the same way on js2, so it is not a module fault. Cause not investigated.

The goal "0 lost passes" is not met. The loss will shrink as js2 builds these features.

## Other tests

- `cargo test --offline -p bare-js2 --lib`: 575 passed, 0 failed. That includes 30 tests in `module_tests.rs` (one runs with a tiny GC trigger).
- Shared suite (`cargo test -p bare-js-api --features suite --test engines`): 60 passed on the old engine and on js2, with and without GC stress. Three tests are new.

## Not built and not tested

- Top-level await: `module_parse` throws `Unsupported("top-level await")`.
- Namespace properties are accessors, not data properties (the old engine does the same). They are not configurable and not writable through assignment.
- Import attributes are ignored. `import.meta` has only `url`.
- Dynamic import in the shared suite checks only the request and `fail_dynamic_import`: `Engine::drain_microtasks` and `promise_status` are still `Unsupported` in js2, so the suite cannot read the result. The test262 runner uses engine-specific calls for that.
- Not run: the Windows build and tests, a browser journey with `<script type="module">`, the full cost matrix.

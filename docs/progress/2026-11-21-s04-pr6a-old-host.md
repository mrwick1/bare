# 2026-11-21: S0.4 PR 6a, the old `eval::Host` impl of `Dom` is gone

Branch `t3/s04-pr6a-old-host`. It holds #825 (`t3/s04-pr5-owners`) and #834 (`t3/host-fill-named-write`) as merge commits, because neither was merged when I started. Merge `origin/main` again when they land. The PR has no auto-merge.

## What changed

- `crates/bare/src/browser.rs`: `impl eval::Host for Dom` is removed (`call`, `fill_indexed`, `named_write`). `bare_js_api::Host::fill` and `named_write` hold the dispatch now. The realm has no old host: `Interp::set_host(dom)` is not called.
- The named writers of `browser_dataset.rs` and `browser_navigation_storage.rs` take `(owner, name: &[u16], op)` and not a `NamedRequest`. The engine gives the name as text, so the writers do not intern it again and convert it back.
- `crates/js/src/eval_api.rs` (`api_named_write`): a name of up to 48 units goes through a stack buffer, and the values go through a 4-slot array. It was two `Vec`s for each write.
- `browser_textarea::install` and `browser_handlers::install_onabort` make their members from `table!` rows (`install_rows`), with the same attributes as `def_get_s`.

## Cost

Machine archMachine, loaded by other agents: instruction counts only (`tools/js/cost_matrix.sh`, minimum of 3 runs). Base is the merge commit `8c9e784b` (this branch without the change). Rows: `dataset_load|attr_load|navigation_load|style_load|nodelist_load|platform_load|browser_load|session_load|streams_load|handler_load|select|scripts_load` (98 rows).

First version (the writers as before, two `Vec`s): `dataset_load write 10000 1` +8.65%.

After the two changes above, default build, glibc:

| Row | Base | New | Change |
| --- | --- | --- | --- |
| `dataset_load write 10000 1` | 118,830,190 | 120,317,282 | +1.25% |
| `dataset_load write 10000 50` | 150,175,457 | 151,524,411 | +0.90% |
| `dataset_load write 1000 1` | 18,181,423 | 18,317,953 | +0.75% |
| `dataset_load read 10000 50` | 178,989,408 | 180,321,762 | +0.74% |
| `dataset_load keys 10000 50` | 3,137,083,159 | 3,206,254,205 | +2.21% |
| `dataset_load keys 1000 50` | 330,442,778 | 337,351,367 | +2.09% |
| `attr_load react 10` | 2,081,532,619 | 2,092,704,689 | +0.54% |

At `codegen-units=1` on both trees: `attr_load react 10` +0.457% (passes). The `dataset_load` rows are over +0.5% at `codegen-units=1` too (keys 10000 50 +1.99%, keys 1000 50 +1.89%, write 10000 1 +1.15%, write 10000 50 +0.82%, read 10000 50 +0.66%). **These rows fail the cost rule.**

Cause (callgrind of `dataset_load keys 1000 50`, profiling build, 344.0 M against 351.0 M): the fill step. The heap asks `Host::fill` 52,000 times in this row. The old route called `Dom::fill_indexed` (191 instructions). The interface route calls `Interp::api_fill` (124 instructions of its own: host key, push on the handle stack, `enter`, `truncate`) and then `Dom::fill` (201). About 135 instructions more for each fill, 7 M in total. The other functions do not change. Writes show the same cost for the scope (about 150 instructions for each write).

The 135 instructions are the bridge: a scope and a handle for an object that `Dom::fill` turns back into an `ObjId`. They go away only if the call needs no scope. Options are in the PR text.
